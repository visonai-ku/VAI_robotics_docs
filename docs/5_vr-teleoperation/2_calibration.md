# 개인 보정

:::info[시작 전 확인]
- [ ] [환경 구축](../3_pipeline/1_setup.md) 완료 — conda 환경 `ri_motion_v5_py312`, 커널 등록
- [ ] Quest가 Wi-Fi `AIWORKER1115` 에 연결되어 있고, 맥북도 192.168.6.x 네트워크에 있음
- [ ] 다른 Quest 수신 노트북을 **STOP 해서 `8443` 포트를 비웠음**
:::

:::note[로봇은 필요 없습니다]
보정은 Quest 컨트롤러만으로 합니다. 로봇 전원, bringup, inbound·outbound 모두 필요 없습니다.
:::

## 개요

사람마다 "앞으로", "왼쪽으로", "위로" 움직일 때의 손 궤적이 다릅니다. 앞으로 밀면서 살짝 아래로 내려가거나, 옆으로 옮기면서 몸쪽으로 당겨지는 식입니다. 이 문서는 **개인별 왕복 궤적을 수집해 위치 보정 행렬을 만드는 보정 절차**를 다룹니다.

보정을 하면 컨트롤러를 "앞으로"라고 의도한 방향이 로봇의 `+X` 로 더 정확히 매핑됩니다. 보정 없이 배포된 `v1` 프로필을 그대로 써도 동작은 하지만, 특정 사용자의 보정값이지 범용 보정값이 아닙니다. 본격적인 데이터 수집 전에 본인의 보정 파일을 만들어 두는 편이 좋습니다.

## 1. 수집 준비

1. `calibration_notebook/calibrate_intent_axes.ipynb` 를 **새 커널**에서 위부터 실행합니다.
2. 설정 셀의 기본값을 확인합니다.

   | 항목 | 기본값 | 의미 |
   | --- | --- | --- |
   | `PC_HOST` | 자동 감지 | Quest에서 접근할 맥북 LAN IP. 틀리면 직접 지정 |
   | `QUEST_PORT` | `8443` | Quest가 접속할 포트 |
   | `PREPARE_S` | `3.0` | 매 회차 준비 시간(초) |
   | `CAPTURE_S` | `6.0` | 매 회차 기록 시간(초) |
   | `MAX_WRIST_ROTATION_DEG` | `30.0` | 시작 방향에서 허용하는 손목 회전(°) |
   | `RESUME_CAPTURE_PATH` | `None` | 새 보정은 `None` 으로 시작 |

3. 실행 셀로 수집 창을 연 뒤, Quest 브라우저에서 출력된 `https://192.168.6.xxx:8443/` 에 접속해 VR 세션을 시작합니다.
4. 양손 추적과 마지막 패킷 수신 상태를 확인하고 **수집 시작 가능** 표시를 기다립니다.

## 2. 수집

Quest 방향·본인 위치·몸통을 유지한 채, 팔꿈치를 편하게 굽힌 **작업 자세**에서 시작합니다. 손목 방향을 최대한 유지한 채 두 손을 함께 움직입니다. grip은 쥐지 않아도 됩니다.

:::warning[좌우 동작에서 몸을 쓰지 마세요]
몸통을 회전하거나 양팔을 벌리면 축 추정이 틀어집니다. 두 손을 **평행하게** 옮깁니다. 왼쪽이 `+Y`, 오른쪽이 `-Y` 입니다.
:::

| 동작 | 수행 | 사용 |
| --- | --- | --- |
| 전진 | 높이를 유지하려는 의도로 앞으로 이동 후 복귀 | 5회 모두 행렬 계산 |
| 왼쪽 | 높이·앞뒤 거리를 유지하며 `+Y` 로 평행 이동 후 복귀 | 5회 모두 행렬 계산 |
| 상승 | 앞뒤·좌우를 유지하려는 의도로 위로 이동 후 복귀 | 5회 모두 행렬 계산 |
| 오른쪽 | `-Y` 로 평행 이동 후 복귀 | 5회 모두 행렬 계산 |

4종 × 5회, 총 20회를 모두 보정 행렬 계산에 씁니다. 예전의 대각선(왼쪽＋상승, 오른쪽＋상승) 수집은 없어졌습니다.

동작을 고르고 **선택 동작 5회 수집**을 누릅니다. 매회 3초 준비 후 6초 기록입니다.

- 기록 **시작과 끝에 각각 0.3초 이상 정지**합니다.
- 10~20cm 정도의 편한 범위에서 이동했다가 **시작 위치로 돌아옵니다.**
- 손목 회전은 시작 방향에서 **30° 이내**로 유지합니다.

### 회차가 거절됐을 때

거절된 회차는 완료 횟수에 포함되지 않습니다. 원인을 확인하고 같은 시작 버튼을 누르면 이어서 진행할 수 있습니다.

| 상황 | 조치 |
| --- | --- |
| 특정 동작만 다시 받고 싶다 | **선택 동작만 다시 수집** — 그 동작의 완료 기록만 제외 |
| Quest 세션·origin·헤드셋 기준이 바뀌어 중단됐다 | **전체 기준/수집 초기화** 후 4종 전부 다시 수집 |

## 3. 저장

4종 × 5회가 끝나면 **보정 계산 미리보기**로 확인한 뒤, 제어창의 **Calibration 이름**에 본인의 영문 이름을 넣고 **저장·보정 계산 후 종료**를 누릅니다. 이름은 수집 중에 미리 넣어 둬도 됩니다.

파일 이름은 저장 날짜 기준 `YYMMDD_이름` 형식입니다. 2026년 9월 23일에 `jaehoon` 을 입력하면 `260923_jaehoon.json` 이 됩니다. 이름은 40자 이내의 영문·숫자·공백·`_`·`-` 만 쓸 수 있습니다.

| 내용 | 저장 위치 |
| --- | --- |
| 전체 수집 원본 | `calibration/diagnostics/<YYMMDD_이름>_trajectory.json` |
| 반복별 수집 기록 | 같은 이름의 `.jsonl` |
| **행렬 계산 완료** 프로필 | `calibration/profiles/<YYMMDD_이름>.json` |
| 미완료 또는 행렬 계산 실패 | `calibration/diagnostics/<YYMMDD_이름>.json` |

기존 파일을 덮어쓰지 않습니다. 빈 이름이거나 같은 날짜·이름이 이미 있으면 저장 버튼이 비활성화되니 다른 이름을 넣으세요. 창을 X로 닫아도 그때까지의 수집은 저장되며, 유효한 이름이 없으면 실행 시각 기반 이름으로 자동 저장됩니다. 새로 만든 개인 데이터와 프로필은 **Git에서 제외**됩니다.

## 4. 결과 해석

:::warning[`fit_success=true` 가 "잘 된다"는 뜻은 아닙니다]
`fit_success=true` 는 **20회 수집과 행렬 계산이 끝났다**는 뜻일 뿐, 실제 사용감이나 작업 성공률, 로봇 안전성을 보장하지 않습니다. 예전의 궤적 점수 검사(`accepted`)는 없어졌습니다.
:::

결과 셀에서 `fit_success`, `reason`, 각 손의 조건수·보정 행렬과 저장 경로를 확인합니다. 수집 단계의 추적·패킷·회전·왕복 구간 확인과 행렬 유효성(조건수 등) 확인은 그대로 적용되므로, `fit_success=false` 라면 `reason` 으로 미완료인지 계산 실패인지 봅니다.

## 5. 프로필 적용

수집 창을 종료해 `8443` 을 비운 뒤, `real_vr_teleop.ipynb` · `real_vr_teleop_record.ipynb` (또는 `sim_vr_teleop.ipynb`)를 평소처럼 실행합니다. **설정 셀은 고치지 않아도 됩니다.** 프로필은 실행 창(MuJoCo 컨트롤 창)의 **작업자 보정** 목록에서 고릅니다.

| 목록 항목 | 내용 |
| --- | --- |
| `보정 미적용 (identity)` | 보정 없이 컨트롤러 이동을 그대로 사용 |
| `v1 원본 (v1.json)` | 배포된 v1 행렬. 재계산하지 않음. 설정 셀의 시작값 |
| `<파일명> · calibration/profiles` 등 | 작업자 프로필 |

1. 목록에서 파일명을 누르면 별도 적용 버튼 없이 바로 불러옵니다.
2. 목록 아래 `적용:` 줄에서 파일명·ID·경로를 확인합니다.
3. 실행 중에 새로 저장한 파일은 **새로고침**을 눌러야 목록에 나옵니다.

- `calibration/profiles/` 와 `calibration/diagnostics/` 의 프로필 JSON이 목록에 나옵니다. 원본 궤적(`*_trajectory.json`)은 나오지 않습니다.
- 파일명을 `jaehoon.json` 처럼 바꿔도 내부 행렬과 profile ID는 그대로입니다.

:::warning[바꿀 수 있는 때]
- **DRY RUN 대기 중**: Quest 추적 없이 바꿀 수 있습니다. 바꾼 값은 REAL RUN으로 전환해도 유지됩니다.
- **REAL RUN**: 양손 추적이 유효하고 grip을 모두 놓은 상태에서만 적용됩니다.
- **조작·복귀·녹화 중**: 목록과 새로고침이 잠깁니다.

로봇 앞에서 추적이 불안하면 **DRY RUN에서 프로필을 고른 뒤 REAL RUN으로 전환**하세요.
:::

- 잘못된 파일을 고르면 현재 보정을 그대로 두고 `변경 실패 (파일명): 이유` 를 표시합니다. 나중에 자동으로 다시 시도하지 않습니다.
- 보정 행렬만 바뀝니다. Initial pose 목표, 속도, 다음 grip 기준은 그대로입니다.
- 설정 셀을 다시 실행하면 그 셀의 `PROFILE_PATH`(기본값 v1)로 돌아갑니다. 매번 본인 프로필로 시작하고 싶다면 설정 셀의 이 줄만 바꿉니다.

```python title="real_notebook/real_vr_teleop_record.ipynb — 설정 셀"
PROFILE_PATH=PROJECT_DIR / "calibration/profiles/<YYMMDD_이름>.json",
```

:::tip[SIM 확인은 선택입니다]
처음 쓰는 프로필은 `sim_notebook/sim_vr_teleop.ipynb` 에서 작은 전진·좌우·상승 움직임으로 사용감을 먼저 봐도 좋습니다. SIM 확인 기록은 REAL 사용의 조건이 아닙니다.
:::

REAL은 **DRY RUN에서도 실제 로봇 피드백이 필요**합니다. [로봇 구동](../3_pipeline/2_robot-start.md)을 먼저 끝내고 [실행](./3_run.md) 절차로 연결과 DRY RUN을 확인하세요.

## 자주 겪는 문제

| 증상 | 원인 / 해결 |
| --- | --- |
| Quest에서 보정 페이지가 안 열림 | 다른 노트북이 `8443` 을 쓰는 중. 그 노트북 STOP 후 커널 재시작 |
| `PC_HOST` 자동 감지가 틀림 | 설정 셀에서 맥북 LAN IP를 직접 지정 |
| 회차가 계속 거절됨 | 시작·끝 정지 0.3초, 손목 회전 30° 이내, 시작 위치 복귀를 확인 |
| 저장 버튼이 비활성화 | 이름이 비었거나 같은 날짜·이름 파일이 이미 있음 |
| 새 프로필이 작업자 보정 목록에 없음 | 실행 중에 저장한 파일은 **새로고침** 필요 |
| 목록에서 골라도 바뀌지 않음 | 조작·복귀·녹화 중이라 잠김. REAL RUN이면 양손 추적이 유효한 상태에서 grip을 모두 놓고 다시 선택 |
| `변경 실패 (파일명): ...` | 미완료·손상된 프로필. 현재 보정은 그대로 유지됨. 결과 셀의 `fit_success` · `reason` 확인 |
| `unexpected keyword argument 'CONFIRM_CALIBRATION_SETUP'` | 예전 설정이 남아 있음. 아래 [예전 설정](#예전-설정을-쓰고-있다면) 참고 |

### 예전 설정을 쓰고 있다면

`CONFIRM_CALIBRATION_SETUP`, `ALLOW_FAILED_PROFILE_IN_SIM`, `SIM_CANDIDATE_CAPTURE_PATH`, `REAL_CANDIDATE_CAPTURE_PATH`, `REAL_CANDIDATE_REVIEW_PATH` 는 **없어진 설정**입니다. 노트북 설정 셀에 남아 있으면 오류가 나니 해당 줄을 지우고 설정 셀부터 다시 실행하세요. 이제 프로필 JSON 하나만 있으면 됩니다.
